# 🚀 Release Process

> Processo oficial de publicação do Abrigo.

---

# Objetivo

Definir um processo padronizado para lançar novas versões do Abrigo.

---

# Fluxo

Desenvolvimento

↓

Testes

↓

Correções

↓

Commit

↓

GitHub

↓

Deploy

↓

Publicação

---

# Etapa 1

Desenvolvimento

Implementar apenas uma funcionalidade por vez.

---

# Etapa 2

Testes

Verificar:

- Mobile

- Tablet

- Desktop

- Responsividade

- Performance

- Console

---

# Etapa 3

Correções

Corrigir:

- Bugs

- Layout

- Imports

- Performance

---

# Etapa 4

Commit

Exemplo

```
feat(calendar): adiciona eventos recorrentes

fix(home): corrige animação

docs: atualiza roadmap
```

---

# Etapa 5

Push

Enviar para o GitHub.

---

# Etapa 6

Deploy

Realizar deploy na Vercel.

Verificar se:

- Build passou

- Não existem erros

- Aplicação abriu corretamente

---

# Etapa 7

Atualizar documentação

Sempre atualizar:

- CHANGELOG

- ROADMAP

- README

Quando necessário.

---

# Versionamento

Seguir Semantic Versioning.

```
MAJOR.MINOR.PATCH
```

Exemplos

```
2.0.0

2.1.0

2.1.1

3.0.0
```

---

# Checklist

Antes de publicar verificar:

☐ Projeto compila

☐ Sem erros no console

☐ Responsividade

☐ Performance

☐ Testes concluídos

☐ Documentação atualizada

☐ Changelog atualizado

☐ Roadmap atualizado

☐ Build funcionando

☐ Deploy concluído

---

# Objetivo

Garantir que cada nova versão do Abrigo seja publicada de forma organizada, segura e previsível.
